# cheerox — implementation plan and status

Rust-powered, near drop-in replacement for **Cheerio 0.22.0**, built on the
Rusteerio engine (NAPI-RS native DOM/parse/select/serialize, TypeScript
facade). This file tracks milestones, key decisions, and the exact next
steps. See `COMPATIBILITY.md` for the behavioral report and `UPSTREAM.md`
for the pinned revisions.

### Phase D — Parser and DOM compatibility (DONE for the suite; keep hardening)
- Legacy default options `{ withDomLvl1: true, normalizeWhitespace: false,
  xmlMode: false, decodeEntities: true }`; parsing goes through the native
  htmlparser2-mode tokenizer in fragment mode.
- Node shapes under `_legacyDom` (nodes.ts): `parent` reads null at top
  level, `root` field (weakmap-backed, literal assignment semantics),
  domhandler 2.4.2 Lvl1 aliases on every node, root keeps `name: 'root'` +
  `attribs`, and OWN enumerable accessors for the 0.22.0 field set so
  `Object.keys(node)` and deep equality match plain objects.
- Serialization: dom-serializer 0.1.x + entities 1.1 port (raw
  script/style, bare empty attrs in HTML mode, `&#x…;` non-ASCII, void
  elements, doctype/CDATA/svg rules).
- Selection: css-select 1.2.0 semantics including the `:scope` acceptSelf
  rule, leading `>`/`+`/`~` anchoring, SyntaxError on invalid selectors,
  and rejection of post-0.22.0 pseudos (`:eq`, `:is`, …) with the original
  `unmatched pseudo-class` message.
- Structural rule: tree surgery installs whole child lists
  (`writeChildren`); the arena rebuilds sibling/parent links. Raw pointer
  writes on attached nodes fight the engine's invariants (a detached
  `next` target makes the written node vanish) and are never used.

## Known performance profile (see docs/BENCHMARK.md)

Faster: parsing (1.8–2.3x). Slower than the oracle today: per-node
operations over loaded trees (queries 0.58x, mutations 0.17x, serialization
0.31x) because the facade materializes live views over the native arena
while 0.22.0 operates on plain JS objects from parse time. Next planned
optimizations, in order of expected payoff:

1. Native port of the dom-serializer 0.1.x rules (removes per-node hops in
   all `$.html()`/`.html()`/`toString()` paths).
2. A scoped-select native op that returns matches for `{selector,
   contextIds, roots}` in one call (removes the `select('*')`
   materialization step in `scopedSelect`).
3. Batched attribute writes for `attr(map)`/`addClass` loops.

## Key architectural decisions

1. **Two facades, one engine.** The root entry is the 0.22.0 API; the
   Rusteerio 1.2.0 facade moved to `src/modern.ts` (`cheerox/modern`). Both
   share the native arena, selectors, and serializer infrastructure. The
   777-test 1.2.0 upstream suite runs against `cheerox/modern`.
2. **Legacy node shape is per document, not global.** `_legacyDom: true` in
   a document's options switches `viewConstructor` to legacy prototypes
   (cache key `type:legacy`), so modern documents are byte-identical to the
   Rusteerio behavior (proven by the unchanged 777-test suite).
3. **Arena owns structure.** 0.22.0's raw `prev`/`next`/`parent` writes are
   reproduced by installing whole child lists; per-node writes only happen
   on detached nodes or through the engine's own operations. This was
   forced by an engine invariant: writing a sibling pointer toward a
   detached node made the written node vanish from its parent.
4. **Serialization and selector semantics are ported, not proxied.**
   dom-serializer 0.1.x + entities 1.1 (5 XML chars + all non-ASCII as
   numeric refs) and css-select 1.2.0 scoping (acceptSelf, anchors,
   allowlist) live in `src/legacy.ts` and match the oracle byte-for-byte on
   the tested surface.
5. **Oracle-first acceptance.** When the vendored tests disagree with what
   today's `npm install cheerio@0.22.0` produces, we match the ORACLE (the
   installable reference) and document the drift. The one known case is the
   empty-attribute HTML rendering (dom-serializer 0.1.1 vs the 2016 pin).
