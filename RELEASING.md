# Releasing rusteerio

The public npm package name is **`rusteerio`**, maintained by the context.dev
team. Releases include all eight native binaries, self-contained TypeScript
declarations, source files and license notices. Consumers install no additional
npm packages and need no Rust toolchain on supported platforms.

## Trusted publishing

The repository must be publicly visible for the publishing workflow's
provenance checks. The workflow publishes exclusively through npm trusted
publishing with OIDC; it has no token-authentication or bootstrap path.

Configure the GitHub Actions trusted publisher in the existing npm package's
settings:

| Field | Value |
| --- | --- |
| Organization | `context-dot-dev` |
| Repository | `rusteerio` |
| Workflow filename | `publish.yml` |
| Environment | `npm` |
| Allowed action | Direct publishing with `npm publish` |

Configure the GitHub `npm` environment for maintainers and permit releases from
`main`. The workflow uses GitHub-hosted runners, Node 24, npm 11.5.1 or newer,
and OIDC authentication. It requires no stored npm token.

A new trusted-publisher configuration must complete its first successful
publication within two days. Prepare and publish a new version within that
window; an existing npm version cannot be republished to validate the
configuration. If it expires, delete and recreate it when the next release is
ready. See [npm's trusted-publishing
documentation](https://docs.npmjs.com/trusted-publishers/) for configuration and
expiry details.

After the first successful OIDC release, revoke the obsolete bootstrap token
in npm and delete `NPM_BOOTSTRAP_TOKEN` from the GitHub `npm` environment. That
credential was used only to establish initial package ownership and is not
needed by this workflow.

## Prepare a version

Update `package.json`, `package-lock.json`, `Cargo.toml` and `Cargo.lock` to the
same semantic version. Regenerate the notices with `npm run notices:generate`
and merge the release changes to `main`. Use `next` for prerelease versions.
Confirm the build, tests and packaging checks pass.

Create a version tag on the current `main` commit:

```sh
git switch main
git pull --ff-only
git tag v0.1.1
git push origin v0.1.1
```

Replace `0.1.1` with the intended version. Dispatch publication before making
another commit to `main`: the tag, package version, Cargo version and the
workflow's `main` commit must identify the same release.

## Publish a release

Run the **Publish to npm** workflow from `main`, with the exact package version
and npm dist-tag:

```sh
gh workflow run publish.yml \
  --repo context-dot-dev/rusteerio \
  --ref main \
  -f version=0.1.1 \
  -f npm_tag=latest
```

The workflow validates the public repository and exact release commit, runs the
complete build/test matrix, assembles one tarball, and checks its source,
license, metadata, checksum and all eight native binary architectures. It
installs and tests that exact artifact before publishing it with provenance.

Pushes, pull requests, and ordinary CI runs build and test without publishing.
Publication requires the separate manual workflow and any configured `npm`
environment protection. Normal OIDC releases require no stored npm token.

## Package checks

For a local development build:

```sh
npm run build
npm run test:package
npm run release:check -- --local
```

For a complete release artifact containing all targets:

```sh
npm run release:check -- --tarball release --commit <release-commit>
npm run test:package -- release
```

`release:check` rejects missing binaries, incorrect architectures, accidental
package files, missing notices, version mismatches and npm runtime dependencies.
The CI-produced `manifest.json` records the commit and tarball checksum for
publication verification. Provenance is generated by npm's supported CI
publishing flow; see [npm's provenance
documentation](https://docs.npmjs.com/generating-provenance-statements/).

Linux GNU builds run inside pinned glibc 2.28 images on both architectures.
The binary audit reads ELF symbol-version requirements and rejects binaries
requiring newer glibc, a C++ runtime, or the wrong libc. Windows releases include
both x64 and arm64; their PE machine headers are checked. The package includes
the exact patched html5ever/markup5ever/html5gum sources and original notices alongside
Rusteerio's source. Regenerate third-party notices after any Cargo dependency
or compiler change.
